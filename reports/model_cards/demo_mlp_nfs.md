# Model card: demo detector (MLP on NFStream flows, `mlp-nfs-nfs17-s0-…`)

Active model of the live system (C13–C16). Generated by `scripts/make_model_cards.py`.

## Data

- Training: CIC-IDS2017 Monday, Wednesday and Friday PCAPs → NFStream (frozen `configs/nfstream.yaml`, TCP termination plugin) → LycoS17 labelling rules (`nfs17`). Time-block split; Wednesday 13:30–13:55 UTC held out entirely (it is replay segment A).
- Features: 59 NFStream statistical features (`configs/tracks/nfs.yaml`).
- Threshold: 95% DR on source validation, frozen.

## Performance

- Within nfs17 (3 seeds): FPR 1.2–2.3% at DR 94–95%, MCC 0.90–0.94.
- On CSE-CIC-IDS2018 (nfs18 test): FPR 4.7–5.5%, DR 0.1–1.1%.
- Demo replay, seed 0: benign FPR 0.93% on segment A (held-out 2017) vs 8.93% on segment B1 (2018); DoS-Hulk DR 94% → 1.2%.

## Known failure cases

- A different network breaks it: false positives rise about 10×, mostly on 2-packet flows to SMB / telnet / HTTPS / SSH, and the 2018 DoS-Hulk is missed.
- It flags the 2018 'DoS-SlowHTTPTest' (refused connections to port 21) because they look like port scans, not because it recognises slow HTTP.
- Label-free adaptation does not fix the new network: AdaBN / scaling / CORAL raise canary FPR to 13–41% and are blocked by the gates; only XGBoost few-shot with labelled flows from the new network passes them (segment-B1 FPR 10.75% → 0.5–1.5%).
- C17: as a self-updating Tent loop, an attacker who can query its score and controls 5–10% of the adaptation traffic drives DDoS detection from 100% to 1.6% within 30 rounds, without raising FPR. Guards anchored to the original model (canary, rollback) stop this; per-step checks do not.

## Intended use

Live demonstration of drift detection and human-approved adaptation on replayed lab traffic.
